# 양방향 번역 — Lumiverse 확장

[Lumiverse](https://lumiverse.chat/)에서 응답과 내 메시지를 AI로 번역하는 양방향 번역 Spindle 확장입니다. Marinara Engine의 번역 기능을 참고해 만들었고, 아래를 합쳤습니다.

- 번역 프리셋·단어장 **1.10.0**의 화면과 기능([tlsiddl/marinara-translation-tools](https://github.com/tlsiddl/marinara-translation-tools), 원작 [minikkuen/Marinara-Translation-Tools](https://github.com/minikkeuen/Marinara-Translation-Tools)): 문단별 번역 보기, 대조·수정(문단별 **다시 번역**), 프리셋, 채팅별 단어장, 기타 지침과 보관함, 대사 지침, 이전 대화 참고, 말투·단어·세계관 자동 정리, NPC 자동 수집, 설정 백업. 원작 `extension.js`를 `src/vendor/tt-1.10.0/`에 **바이트 그대로** 두고 통째로 실행합니다(`npm run verify:original`로 원작과 비교). 호스트 차이는 `src/host-emu/`에서만 흡수합니다. 원저작자의 허락을 받아 업데이트를 이어서 따라가며, 이 확장은 원본이 아니고 원저작자의 것을 제 것이라 주장하지 않습니다.
- Marinara Engine의 기본 AI 번역에서 가져온 것: 응답 자동 번역, 내 메시지 번역, 입력창 번역 버튼
- Lumiverse용으로 더한 것: 번역하지 않을 부분(상태창 등) 지정, HTML 구조 보존(내 메시지 번역), 번역 지침 묶음, 기억 서재 연동(lv-tx v1)

Lumiverse에는 기본 채팅 번역 기능이 없어서, 번역은 이 확장이 모두 맡습니다.

## 0.5.10

스와이프를 지운 뒤 번역 기록이 엉뚱한 스와이프에 붙던 문제를 고쳤습니다. 루미버스는 스와이프를 지우면 번호를 다시 매기지만 확장이 저장한 번역 기록(스와이프 번호가 키)은 옮기지 않아서, 지운 스와이프의 번역이 다음 스와이프에 붙고 범위 밖 키가 남았습니다. 이제 삭제 때 지운 번호의 기록을 버리고 더 큰 번호는 하나씩 당깁니다(한 번의 저장, 다른 확장의 데이터는 그대로). 이전 버전에서 이미 어긋난 메시지는 글을 열 때 본문 대조로 확실한 것만 바로잡습니다. 또 HTML 카드(Sola 보드·이젤·선택지 카드 등)에서 번역을 켜면 아이콘이 커지거나 제목이 내려가고 선택지 글이 한 글자씩 꺾이던 레이아웃 문제를 고쳤고(flex/grid 안의 번역 래퍼를 레이아웃 투명으로), `aria-hidden` 장식(보드 가로줄 A–H)은 번역하지 않습니다. 또 생각 블록(`<think>` 등) 안에 `<tracker>` 같은 태그 이름이 글자로 들어 있으면 번역 버튼이 먹통이 되던 문제를 고쳤습니다: 생각 블록 태그(think·thinking·reasoning)는 이제 항상 번역에서 제외됩니다(제외할 태그 목록에 적지 않아도 되고, 저장한 목록은 그대로입니다). 번역할 문단이 없을 때 버튼이 조용하던 것도 안내 문구가 뜨게 했습니다. 「긴 메시지 접기」를 켠 채 번역을 보면 「더 보기」가 안 열리던 것도 고쳤습니다. 원작 무수정.

## 0.5.9

실호스트(Lumiverse 7880)에서 화면에 있는 메시지도 원문 분할로 번역돼 머리말·`<pass>/<fail>`·Auto-parse 메시지의 칸이 비던 문제를 고쳤습니다. 루미버스가 `data-message-id`를 행 래퍼와 메시지 카드 둘에 달아 원작이 화면 칸을 못 찾던 것이 원인이었습니다(어댑터만 수정, 원작 무수정). 0.5.7의 「Auto-parse 영향 없음」은 정정합니다: 영향이 있었고 0.5.9에서 해소됩니다.

## 0.5.5

리뷰어 검수 조건 해소. island의 `<style>`이 앱 전체로 새던 문제를 고쳤고(번역 전에도 island가 뜨면 생겼음), 확장을 끄면 숨은 복사본과 관찰자를 모두 정리합니다.

**알려진 한계(HTML 블록):** 원작은 화면 밖 메시지를 원문 텍스트(빈 줄 기준)로 나눠 키를 만들기 때문에 island 블록과 맞지 않을 수 있습니다(0.5.6부터: 생성 직후엔 메시지가 그려지길 기다려 번역하고, 화면 밖에서 번역된 메시지가 화면에 오르면 번역 없는 칸을 원작 경로로 한 번 자동으로 이어서 번역합니다. 모델 호출이 1회 더 들므로 설정의 「화면에 나타날 때 빠진 칸 자동 보충 번역」(기본 켬)으로 끌 수 있습니다). 번역 시점에 복사본이 없던 화면 위 메시지는 「이어서 번역」으로 채웁니다.

## 0.5.4

HTML 블록(상태창·카드·`<details>` 행동 힌트·DEM/Fate 카드) 안의 글도 번역해 읽기 화면에 제자리로 보여 주고, 비교 창과 읽기 화면의 단위가 맞습니다. 빈 하단 줄(`- 없음`)은 번역에 보내지 않습니다.

## 0.5.3

실제 호스트에서 나온 문제를 고쳤습니다. 원작 `extension.js`는 그대로입니다(`verify:original` 9개 동일).

- **설정 화면이 하나**입니다. 연결·언어·자동 번역·내 메시지 번역·제외 규칙·지침 묶음이 원작 설정 안의 구역이고, 원작의 저장 버튼 하나로 모두 저장됩니다.
- 저장이 "저장 중"에서 멈추지 않고(답이 없으면 20초 뒤 읽어 확인하거나 오류로 끝남), 저장 버튼·확인 창의 주요 버튼 글씨가 모든 테마에서 보입니다.
- 번역 뒤에도 긴 메시지의 "더보기"가 열리고, 상태창·카드·접는 블록이 번역 화면에 그대로 보입니다.
- 번역이 일부만 된 메시지에 **이어서 번역**, 설정에 **한 번에 번역할 최대 글자수**가 생겼습니다.

## 0.5.2

리뷰어 검수(SYHO-229) 조건 해소. 원작 `extension.js`는 그대로다(`verify:original` 9개 동일).

- **연 뒤 수정·스와이프가 낡은 원문을 덮어쓰지 않습니다.** 호스트의 메시지 변경(`MESSAGE_EDITED`·`SWIPED`·`SWIPE_EDITED`·`SENT`·`DELETED`)을 원작이 보는 메시지 캐시로 넘깁니다. "영어 원문도 같이 고치기"가 수정을 지우던 문제, 스와이프를 넘긴 뒤 번역하면 다른 스와이프 기록이 섞이던 문제가 닫힙니다.
- **0.4.0 단어장이 원작 설정으로 한 번 옮겨집니다**(원본 보존). 원작 단어장이 비어 있는 동안엔 기억 서재에 이미 공개된 단어장을 비우지 않습니다.
- **채팅 전체를 자동으로 읽지 않습니다.** 생성 뒤 원작의 자동 읽기는 끝 16개로 줄었고, 1000개까지 읽는 것은 사용자가 누른 "번역 안 된 메시지 모두 번역"뿐입니다.
- **되살린 것:** 화면에 들어온 옛 메시지(끝 80개 밖)의 저장된 번역·번역 버튼, 문맥 "번역문 포함", "채팅 설정 유지" 프리셋(0.4.0 채팅별 프롬프트 연결). **숨긴 것:** 후처리 후 번역(루미버스에 후처리 단계가 없음). 정리는 [docs/tt-1.10.0-ui-parity.md](docs/tt-1.10.0-ui-parity.md).
- 그룹 채팅의 화자 이름·말투 자료도 되살렸습니다(구성원은 채팅 메타데이터, 응답은 이름이 정확히 같은 구성원에게). 아직 못 한 것: 브라우저가 닫혀 있을 때의 서버 번역.

## 0.5.0

번역 프리셋·단어장 **1.10.0**의 화면과 기능을 원작 그대로 옮겼습니다. 원작 `extension.js`를 `src/vendor/tt-1.10.0/`에 바이트 그대로 두고 통째로 실행하며(`npm run verify:original`로 원작과 비교), 호스트 입구만 `src/host-emu/`에서 만듭니다. 번역문 표시, 문단 대조·수정 창(문단별 **다시 번역**), 말투·단어·세계관 자동 정리, NPC 자동 수집, 설정 백업이 원작 모양 그대로 나옵니다.

- 옮기지 못한 것·대역·눈으로 볼 목록: [docs/tt-1.10.0-ui-parity.md](docs/tt-1.10.0-ui-parity.md)

## 0.4.0

Translation Tools 1.8.0을 Lumiverse판으로 옮겼습니다. 프리셋·요청 조립·수정 동기화 같은 순수 로직은 원본 코드를 **그대로** 복사했고(`src/vendor/tt-1.8.0/`, SHA-256 고정), 브라우저·Marinara에 묶인 부분만 Lumiverse에 맞게 바꿨습니다.

- **새 프리셋:** 한국어 문체·이름 중심 3종(외국인 대사 병기 2종, 모델 병기 유지 지문만 번역). 한국어로 내는 기본 프리셋은 한글로만 쓰게 하는 줄이 끝에 붙습니다. 기존 번역은 그대로이고 "다시 번역"부터 적용됩니다.
- **프롬프트의 `{{voice}}`·`{{vocab}}`:** 1.8.0 프리셋은 대사 지침과 단어장이 들어갈 자리를 프롬프트 안에 가집니다. 이 자리가 없는 프롬프트(내 프리셋 등)는 전과 같이 뒤에 붙습니다.
- **기타 지침 보관함:** 이름을 붙여 저장하고, 다른 채팅에서 불러옵니다(불러오기는 복사). 예시(지문 문체)를 넣는 버튼이 있습니다. 위의 "번역 지침 묶음"(여러 방이 함께 쓰는 연결)과는 별개입니다. 원본의 한도를 그대로 따라 최대 100개, 이름 60자, 본문 12,000자입니다.
- **번역 고치기:** 메시지 동작 줄의 연필 버튼. 문단별로 번역을 손으로 고치고, "영어 원문도 같이 고치기"를 켜면 AI가 영어 문단을 바뀐 곳만 고칩니다. 원문과 번역은 한 번의 저장으로 함께 바뀝니다. 영어 원문을 되돌리는 기능은 없습니다. 문단 단위로 끝까지 번역된 메시지만 고칠 수 있습니다.
- **페르소나 이름:** 위 한국어 문체 프리셋이면 가장 가까운 이전 내 메시지의 이름을 번역에 알려 줍니다.
- **놓친 최신 답변:** 자동 번역이 켜진 채팅을 열거나 화면으로 돌아왔을 때, 30분 안의 최신 답변이 번역 없이 남아 있으면 번역합니다. 사용자가 중지한 답변은 건드리지 않습니다.
- **기억 서재 연동(LV-TX v1):** 기억 서재가 설치돼 있으면 번역 결과(`metadata.st_translator.pub`)와 채팅 단어장(채팅 메타데이터)을 공개합니다. 이 단어장 공개 때문에 `chats` 권한이 추가됩니다(업데이트 때 다시 승인). 설치돼 있지 않거나 권한이 없어도 번역은 그대로 동작합니다.
- Lumiverse가 `chat-lean-messages-v1`을 지원하면 번역을 시작할 때 채팅 끝 12개만 다시 읽고 번역 기록은 이 확장 칸만 갱신합니다. 지원하지 않으면 0.3.6과 같습니다.
- 이번에 옮기지 않은 것: 말투·단어 자동 수집(캐릭터·페르소나·로어북 권한이 필요합니다. 대사 지침에 `- 사용 언어: 영어`를 직접 적으면 프리셋이 읽습니다), 대조·수정 창의 문단별 재번역, 설정 백업.
- 자세한 내용과 확인하지 못한 부분: [REPORT-tt-1.8.0.md](REPORT-tt-1.8.0.md).

## 0.3.6

- 번역 작업은 채팅 전체를 최대 한 번만 읽고, 진행 저장·표시·버튼 동작은 채팅별 스냅샷을 재사용합니다. 진행 저장은 1초 간격으로 합치고 마지막 결과는 반드시 저장합니다.
- 채팅을 열 때 번역 상태는 최근/화면의 최대 30개 메시지만 받습니다. 이전 메시지를 스크롤하면 화면 가까이에 온 메시지를 추가로 요청합니다. 번역이 없는 메시지는 버튼에 필요한 ID만 받습니다.
- 메시지 수정·삭제·스와이프 이벤트로 캐시를 갱신하며, 다른 채팅으로 이동해도 번역 기록이 섞이지 않습니다. 번역 삭제는 진행 중인 저장이 끝난 뒤 적용합니다.
- 자동 테스트 235개, 타입 검사, 빌드를 통과했습니다. 실측 결과와 API 제약은 [REPORT-fetch-diet.md](REPORT-fetch-diet.md)에 기록했습니다. 이번 버전의 실제 브라우저·모바일 검증은 리뷰어가 진행합니다.

## 설치

1. Lumiverse → Extensions → **Add Extension** → *Install from Source*에 `https://github.com/mallang0723/LV-Translator` 입력 → **Install**
2. 확장을 켜고 권한을 허용합니다.
   - `generation`: 번역 모델 호출, 생성 시작·종료 감지
   - `chat_mutation`: 메시지에 번역 기록 저장
   - `chats`: 채팅 정보(그룹 구성원·연결)와 단어장 공개
   - `characters`, `personas`, `world_books`: 말투·단어·세계관 자동 정리와 그룹 화자 이름이 캐릭터 카드·페르소나·로어북을 읽습니다
3. 서랍(drawer)의 **번역** 탭, 또는 입력창 Extras 메뉴의 **번역 설정**에서 설정합니다.

## 사용법

### 설정은 어디에 있나

번역 탭의 설정은 **하나의 폼**입니다. 원작 1.10.0 설정 화면(번역 프롬프트, 지침, 단어장, 문맥, NPC 자동 수집, 문단 번역, 백업, 공용 프리셋 관리)이 바탕이고, 이 확장의 설정이 **같은 모양의 구역으로 그 폼 안, 저장 막대 바로 위**에 들어 있습니다.

- **번역 연결·언어:** 번역에 쓸 AI 연결, 모델 언어·내 언어, 한 번에 번역할 최대 글자수(비우면 원작 기본), 응답 자동 번역, 내 메시지를 보내기 전에 번역, 입력창 번역 버튼.
- **번역하지 않을 부분:** HTML·코드 보호(내 메시지 번역), 제외 규칙(`/정규식/`, `시작 ... 끝`: 번역에 보내지 않고 번역 화면에 원문으로 남습니다). 태그로 빼는 것은 위 문단 번역의 「번역에서 제외할 태그」에 적습니다.
- **번역 지침 묶음:** 내 메시지 번역에 더해지는 단어집·추가 지침 묶음과 「새 채팅의 기본값으로도 저장」 스위치.
- **저장 버튼은 하나**입니다. 누르면 이 확장의 값(연결 선택 포함)과 원작의 값이 한 번에 저장되고, 상태 표시와 오류는 원작의 상태줄에 나옵니다. 이 확장의 값은 채팅마다 저장되고, 원작의 값은 사용자 저장소 `tt-config.json`에 들어갑니다.

### 메시지에서

- 메시지 동작 줄의 **번역 버튼**(문단 번역)을 누르면 번역하고, 다시 누르면 원문 보기·번역 보기가 바뀝니다.
- 번역은 문단별로 메시지 아래/대신 표시됩니다. 번역된 문단을 누르면 원문이 펼쳐지고, 표시 방식(번역만 / 번역과 원문 함께)은 원작 설정에서 고릅니다.
- 번역문 아래 **하단 바**에서 **대조**(원문·번역 나란히, 문단별 고치기·**이 문단 다시 번역**·**전체 다시 번역**, "영어 원문도 같이 고치기"), 다시 번역, 지우기를 합니다.
- 번역 기록은 스와이프마다 따로 남습니다. 메시지를 수정하거나 스와이프를 넘기면 원작이 이를 알아채고, 번역된 메시지에 새 문단이 생기면 그 문단만 번역합니다.
- 화면에 들어온 옛 메시지는(채팅을 열 때 읽는 끝 80개보다 앞이라도 끝 500개 안이면) 저장된 번역이 나오고 번역 버튼이 동작합니다. 더 앞의 메시지는 "번역 안 된 메시지 모두 번역"(최대 끝 1000개)으로 처리합니다.
- 응답 자동 번역은 **브라우저가 열려 있을 때** 생성이 끝나면 원작이 번역합니다(Stop한 답변·impersonate는 건너뜀). 브라우저가 닫혀 있으면 열 때 놓친 최신 답변을 보충합니다.
- 그룹 채팅에서는 구성원 이름과 말투 자료가 문맥에 들어갑니다. 응답은 메시지 이름이 구성원 캐릭터 이름과 정확히 같을 때만 그 캐릭터로 봅니다(아니면 대표 캐릭터).

### 내 메시지 번역

"내 메시지를 보내기 전에 번역"을 켜면 보낼 때 모델 언어로 번역해 **번역문을 채팅에 저장**하고(실패하면 원문을 보내고 알림), 입력창 옆 **번역** 버튼은 입력 중인 글을 번역해 입력창에 넣습니다. 번역은 원작의 유저 입력 번역 프롬프트·단어장·기타 지침·이전 대화를 따르고, 번역하지 않을 부분(HTML·코드 블록·`{{매크로}}`·제외 규칙·제외 태그)은 이 확장이 보호했다가 되돌립니다. 입력창이 메시지를 만드는 요청(`POST /api/v1/chats/:id/messages`)을 브라우저에서 가로채므로 Lumiverse가 이 방식을 바꾸면 동작하지 않을 수 있고, 멀티플레이 방의 메시지는 번역하지 않습니다.

### 번역하지 않을 부분

한 줄에 하나씩 적는 제외 규칙, 제외할 HTML 태그 이름, HTML·코드 블록·`{{매크로}}` 보호는 **내 메시지 번역**에 적용됩니다(응답 번역의 제외는 원작 설정의 "번역에서 제외할 태그"). 규칙 형식:

```text
<status>                  ← <status ...>...</status> 요소 전체
/HP: \d+\/\d+/            ← 정규식과 일치하는 부분
[상태창] ... [/상태창]     ← 시작부터 끝까지 (" ... " 로 구분)
```

보호한 부분은 번역 전에 `⟦1⟧` 같은 표시로 바뀌고 번역 후 돌아옵니다. 모델이 표시를 빠뜨리거나 늘리면 번역하지 않고 오류로 알립니다.

### 번역 지침 묶음

단어집·추가 지침을 이름 붙여 저장하고 방마다 하나 골라 **내 메시지 번역**에 얹습니다(응답 번역의 단어장·지침은 원작 설정). 편집하면 그 묶음을 쓰는 모든 방의 다음 번역에 반영됩니다.

### 기억 서재 연동

기억 서재가 설치돼 있으면 원작의 번역 기록(보이는 스와이프)에서 `metadata.st_translator.pub`을, 원작 설정의 채팅 단어장에서 채팅 단어장을 공개합니다. 원작 단어장이 비어 있는 동안에는 이미 공개된 단어장을 비우지 않습니다. 0.4.0으로 쓴 단어장은 0.5.2에서 원작 설정으로 한 번 옮겼고 원본(`translator.json`)은 그대로입니다.

### 원작과 다른 점·숨긴 것

- 번역 공급자는 AI 연결만 씁니다(Google·DeepL·DeepLX는 원작 설정 화면에 없는 Marinara 채팅 설정이라 해당 없음).
- **숨긴 것(루미버스에서 동작하지 못함):** "후처리 후 번역" 스위치(후처리 단계 없음). 대화 모드·게임 모드 화면은 루미버스에 없어 나오지 않습니다.
- "기본 번역 버튼도 최신 프리셋"(Marinara 통째 번역 버튼)은 루미버스에 없습니다. 번역 버튼은 항상 원작의 문단 번역입니다.
- 0.4.0 번역 중 문단 단위로 끝난 기록은 원작 기록으로 옮겨져 보입니다. 통째·부분 번역은 보이지 않습니다.
- 브라우저가 닫혀 있을 때의 서버 번역은 지원하지 않습니다.
- 전체 목록과 대역은 [docs/tt-1.10.0-ui-parity.md](docs/tt-1.10.0-ui-parity.md).

## 0.2.0

RP 번역표시 설정 확장 1.0.2(아래 "참고" 절)를 참고해 Lumiverse용으로 구현했습니다.

- **표시 방식 "번역문 먼저"**를 더했습니다. 번역문 아래에 원문이 붙습니다.
- **문단 대조의 문단 안 순서**를 고를 수 있습니다(원문 → 번역 / 번역 → 원문).
- **제외할 HTML 태그 목록**을 더했습니다. 요소 전체를 번역에 보내지 않고 그대로 복원합니다. `<style>`·`<script>` 는 HTML 보호를 꺼도 항상 그대로 둡니다.
- **표시를 모델이 망가뜨렸을 때**, 이전에는 두 번째 실패에서 오류로 끝났습니다. 이제 표시 사이의 글을 하나씩 번역해 이어 붙이는 대체 경로를 먼저 시도합니다.
- 원문에 `⟦1⟧` 같은 글자가 이미 여러 개 있을 때 복원이 어긋나던 버그를 고쳤습니다.
- 표시 방식 대응(참고 확장 → 이 확장):

  | 참고 확장 | 이 확장 |
  |---|---|
  | 번역만 표시 | 번역문만 (기존) |
  | 번역 우선 표시(원문은 접어 둠) | 문단 대조 → 눌러서 원문 (기존) |
  | 원문 우선 표시(번역은 접어 둠) | 원문 + 접힌 번역문 (기존, 메시지 단위) |
  | 번역–원문 함께 보기 | 문단 대조 → 교차, 문단 안 순서 "번역 → 원문" (신규) |
  | 원문–번역 함께 보기 | 문단 대조 → 교차, "원문 → 번역" (기존) |
  | (없음) | 번역문 먼저 / 원문 아래에 번역문 (메시지 단위, 앞의 것이 신규) |

- **설정 위치는 서랍의 번역 탭에 두었습니다.** 참고 확장은 메시지 동작 줄에서 여는 설정창을 쓰지만, 이 확장은 0.1.2에서 동작 줄에 번역·번역 삭제 두 아이콘만 두고 설정은 서랍으로 모았습니다. 호스트 아이콘 크기에 맞춘 줄(휴대폰에서도 44px보다 작음)에 설정 아이콘을 하나 더 얹으면 오터치가 늘고, 표시 방식과 제외 태그는 메시지가 아니라 채팅 단위 설정이라 메시지마다 버튼을 둘 이유도 없습니다. 서랍 패널은 이미 Lumiverse 테마 변수(`--lumiverse-*`)를 써서 밝은 테마·어두운 테마를 그대로 따라갑니다.
- 저장된 번역 데이터 형식은 그대로입니다. 새 설정(`excludeTags`, 문단 안 순서)은 없으면 기본값을 씁니다. 새 권한은 없습니다.

## 0.1.4

- **문단 대조에서 번역 보기/숨기기 버튼을 없앴습니다.** 문단 대조는 원문이 번역과 함께 보이므로 숨길 이유가 없습니다. 번역을 없애려면 메시지 동작 줄의 번역 삭제(文A×) 버튼을 쓰세요. 문단 대조에서 메시지 아래 작은 줄은 번역 중, 오류, 중간에 끊겨 이어서 번역할 때만 나타나고, 정상으로 번역된 메시지에는 나타나지 않습니다.

- 다른 표시 방식(원문 아래, 번역문만, 접힌 번역문)은 그대로입니다.
- 저장된 번역 데이터 형식은 0.1.3과 같습니다.

## 0.1.3

- **번역 삭제는 지금 보이는 스와이프의 번역만 지웁니다.** 이전에는 메시지의 모든 스와이프 번역이 한꺼번에 지워졌습니다. 메시지 동작 줄의 번역 삭제 버튼에 적용됩니다.
- **서랍의 "선택한 메시지" / "메시지 번역" 구역을 없앴습니다**(문단 대조 포함). "대상 메시지: #N", 상태 문구, 새로 번역·이어서 번역·번역 숨기기·이 메시지 저장 삭제 버튼이 빠졌습니다. 메시지마다 자기 버튼이 있어 겹쳤기 때문입니다. 서랍에는 보기·도착 언어·글자 크기 같은 전체 설정만 남습니다. 오류·끊김·이어서 번역·번역 보기/숨기기는 메시지 아래 작은 줄이 맡고, 이 줄은 이제 문단 대조에서도 나타납니다.
- 번역 삭제 버튼은 지금 보이는 스와이프에 번역이 있을 때만 나타나고, 스와이프를 넘기면 따라 바뀝니다.
- 삭제 확인을 누른 뒤 스와이프를 넘기면 확인이 취소됩니다. 사용자가 본 스와이프의 번역만 지워지고, 그 사이 바뀐 스와이프는 건드리지 않습니다.
- 저장된 번역 데이터 형식은 0.1.1·0.1.2와 같습니다. 번역은 원래 스와이프(본문)마다 따로 저장돼 있었습니다. 본문이 완전히 같은 스와이프끼리는 번역을 공유하므로 함께 지워집니다.

## 0.1.2

- 번역 버튼을 메시지 아래에서 메시지 동작 줄(수정·복사·숨김…)로 옮겼습니다. 이미 번역이 있으면 "다시 번역"이 되고, 번역이 있을 때 **번역 삭제** 버튼이 생깁니다.
- 문단 대조 카드를 메시지마다 붙이지 않습니다. 보기·도착 언어·글자 크기·상태·버튼은 서랍의 **문단 대조** 구역으로 옮겼고, 번역 버튼 등으로 고르는 "대상 메시지"에 적용됩니다.
- 저장된 번역 데이터 형식은 0.1.1과 같습니다.

## 0.1.1

- 번역 오류 "No connection profile found. Create one first."를 고쳤습니다. 연결을 바꾸고 저장하지 않으면 적용되지 않는데 알려 주지 않던 문제입니다. 이제 연결 선택은 즉시 저장되고, 저장하지 않은 변경은 눈에 띄게 표시됩니다.
- Lumiverse에 기본 연결이 없어도, 고른 연결이 삭제됐어도 사용할 수 있는 연결로 번역합니다. 연결이 정말 없을 때만 오류를 보여 줍니다.
- 휴대폰에서 글자 15px 이상, 누르는 영역 44px 이상.
